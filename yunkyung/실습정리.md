# 리액트 스터디 실습 정리 - 투두리스트

## 2주차 - Rendering / Component 분리

> 배열 데이터를 활용해 리스트 출력, 반복되는 UI를 컴포넌트로 분리, Props를 이용해 데이터 전달

### 구현 내용

투두리스트의 **화면 출력 부분**을 구현했다. 아직 상호작용(추가/삭제 등)은 없고, 미리 정해둔 배열 데이터를 화면에 그리는 것까지가 목표.

#### 컴포넌트 구조

```
App.jsx            ← todos 배열 데이터 정의, TodoList에 props로 전달
└─ TodoList.jsx    ← todos.map()으로 반복 렌더링
   └─ TodoItem.jsx ← todo 하나를 props로 받아 출력
```

#### 1. 배열 데이터 정의 (`src/App.jsx`)

할 일 목록을 객체 배열로 만들고, `TodoList` 컴포넌트에 `todos`라는 이름의 props로 넘겨준다.

```jsx
const todos = [
  { id: 1, text: "리액트 스터디 예습", done: true },
  { id: 2, text: "투두리스트 만들기", done: false },
  { id: 3, text: "과제 제출", done: false },
];

<TodoList todos={todos} />
```

#### 2. 배열을 map()으로 리스트 출력 (`src/components/TodoList.jsx`)

props로 받은 `todos` 배열을 `map()`으로 순회하면서 `TodoItem`을 하나씩 만든다.
리스트를 렌더링할 때는 각 요소에 고유한 `key`를 꼭 지정해야 한다 (React가 어떤 항목이 바뀌었는지 구분하기 위해).

```jsx
function TodoList({ todos }) {
  return (
    <ul className="todo-list">
      {todos.map((todo) => (
        <TodoItem key={todo.id} todo={todo} />
      ))}
    </ul>
  );
}
```

#### 3. 반복되는 UI를 컴포넌트로 분리 (`src/components/TodoItem.jsx`)

`<li>` 한 줄이 계속 반복되므로 `TodoItem` 컴포넌트로 분리했다.
props로 `todo` 객체 하나를 받아서 텍스트와 완료 여부를 표시한다.

```jsx
function TodoItem({ todo }) {
  return (
    <li className="todo-item">
      <span className={todo.done ? "done" : ""}>{todo.text}</span>
      <span className="badge">{todo.done ? "완료" : "진행중"}</span>
    </li>
  );
}
```

#### 정리

| 개념 | 적용한 곳 |
|---|---|
| 배열 데이터 → 리스트 출력 | `TodoList.jsx`에서 `todos.map()` |
| 반복 UI 컴포넌트 분리 | `<li>` → `TodoItem` 컴포넌트 |
| Props로 데이터 전달 | `App → TodoList (todos)`, `TodoList → TodoItem (todo)` |

## 3주차 - State / 이벤트 처리

> `useState`로 상태 관리, 이벤트(onClick / onChange / onSubmit)로 상태 변경, 자식 → 부모로 이벤트 함수 전달

### 구현 내용

2주차에는 미리 정해둔 배열을 화면에 그리기만 했다면, 이번 주에는 **직접 입력하고 바꿀 수 있는 투두리스트**를 만들었다.

- 날짜를 고르고 그 날의 할 일을 **순서대로** 적는다 (1, 2, 3… 번호 표시)
- 체크박스로 완료 표시, 삭제 버튼으로 삭제
- 할 일을 **클릭하면 상세 화면**으로 들어가서 세부사항을 적을 수 있다

#### 컴포넌트 구조

```
App.jsx              ← 상태(date, todos, selectedId)와 상태를 바꾸는 함수들을 가짐
├─ TodoForm.jsx      ← 할 일 입력 폼 (onAdd)
├─ TodoList.jsx      ← 선택한 날짜의 할 일을 map()으로 출력, 순서 번호 전달
│  └─ TodoItem.jsx   ← 번호 / 체크박스 / 제목(클릭) / 삭제
└─ TodoDetail.jsx    ← 클릭한 할 일의 상세 화면 (세부사항 입력)
```

#### 1. useState로 상태 만들기 (`src/App.jsx`)

화면에서 바뀌는 값은 모두 state로 관리한다. 각 할 일에는 어떤 날짜의 것인지 `date`와 세부사항 `detail`을 함께 저장한다.

```jsx
const [date, setDate] = useState(getToday());      // 선택한 날짜
const [todos, setTodos] = useState([]);            // 전체 할 일 목록
const [selectedId, setSelectedId] = useState(null); // 클릭한 할 일 (null이면 목록 화면)
```

#### 2. 날짜 선택 (`src/App.jsx`)

`<input type="date">`의 값을 state와 연결하고, 선택한 날짜의 할 일만 `filter()`로 골라서 보여준다.

```jsx
<input type="date" value={date} onChange={(e) => setDate(e.target.value)} />

const todosOfDate = todos.filter((todo) => todo.date === date);
```

#### 3. 할 일 추가 - 입력한 순서 유지 (`src/components/TodoForm.jsx`)

폼 안에 입력값을 state로 두고, 제출하면 부모(App)가 내려준 `onAdd`를 호출한다.
App에서는 기존 배열 **뒤에** 새 할 일을 붙이기 때문에 입력한 순서가 그대로 유지된다.

```jsx
// TodoForm.jsx
const handleSubmit = (e) => {
  e.preventDefault();              // 새로고침 방지
  if (text.trim() === "") return;  // 빈 칸은 추가하지 않음
  onAdd(text.trim());
  setText("");                     // 입력창 비우기
};

// App.jsx
const addTodo = (text) => {
  const newTodo = { id: Date.now(), date, text, detail: "", done: false };
  setTodos([...todos, newTodo]);   // 원본을 직접 바꾸지 않고 새 배열로 교체
};
```

#### 4. 순서 번호 (`src/components/TodoList.jsx`)

`map()`의 두 번째 인자 `index`를 이용해 `index + 1`을 번호로 넘긴다.

```jsx
{todos.map((todo, index) => (
  <TodoItem key={todo.id} order={index + 1} todo={todo} ... />
))}
```

#### 5. 완료 토글 / 삭제 (`src/App.jsx`)

state는 직접 수정하지 않고 `map()` / `filter()`로 **새 배열**을 만들어 `setTodos`에 넣는다.

```jsx
// 완료 토글: 해당 id만 done을 뒤집은 새 객체로 교체
const toggleTodo = (id) => {
  setTodos(todos.map((todo) =>
    todo.id === id ? { ...todo, done: !todo.done } : todo
  ));
};

// 삭제: 해당 id만 빼고 새 배열 만들기
const deleteTodo = (id) => {
  setTodos(todos.filter((todo) => todo.id !== id));
};
```

#### 6. 클릭해서 상세 화면 들어가기 (`src/components/TodoDetail.jsx`)

할 일 제목을 클릭하면 `selectedId`에 그 id를 저장하고, App은 `selectedId`가 있으면 목록 대신 상세 화면을 보여준다 (조건부 렌더링).
상세 화면의 `<textarea>`에 입력하면 바로 해당 할 일의 `detail`이 바뀐다.

```jsx
// TodoItem.jsx - 제목 클릭
<button className="text-button" onClick={() => onSelect(todo.id)}>
  {todo.text}
</button>

// App.jsx - 선택한 할 일이 있으면 상세 화면
const selectedTodo = todos.find((todo) => todo.id === selectedId);
if (selectedTodo) {
  return <TodoDetail todo={selectedTodo} onChangeDetail={updateDetail}
                     onBack={() => setSelectedId(null)} />;
}

// TodoDetail.jsx - 세부사항 입력
<textarea
  value={todo.detail}
  onChange={(e) => onChangeDetail(todo.id, e.target.value)}
/>
```

세부사항이 적혀 있는 할 일은 목록에서 📝 아이콘으로 표시된다.

#### 정리

| 개념 | 적용한 곳 |
|---|---|
| `useState`로 상태 관리 | `date`, `todos`, `selectedId`, 입력창 `text` |
| 이벤트 처리 | `onChange`(날짜·입력·체크박스·세부사항), `onSubmit`(추가), `onClick`(삭제·상세 이동·뒤로가기) |
| 불변성 유지 | `[...todos, newTodo]`, `map()`으로 수정, `filter()`로 삭제 |
| 자식 → 부모로 이벤트 전달 | `onAdd`, `onToggle`, `onDelete`, `onSelect`, `onChangeDetail` props |
| 조건부 렌더링 | 할 일이 없을 때 안내 문구, `selectedId`가 있으면 상세 화면 |

#### 아쉬운 점 / 다음에 해볼 것

- 새로고침하면 데이터가 사라진다 → `localStorage`에 저장해보기
- 할 일 순서를 위/아래로 바꾸는 기능

## 4주차 - 라우팅 (페이지 연결 / 페이지 간 이동)

> `react-router-dom`으로 2개 이상의 페이지를 연결하고, 메뉴·링크·버튼으로 페이지 사이를 이동

### 구현 내용

3주차까지는 한 화면 안에서 `selectedId` state로 목록/상세 화면을 바꿔 끼웠다면, 이번 주에는 **주소(URL)마다 다른 페이지**가 나오도록 바꿨다.

| 주소 | 페이지 | 내용 |
|---|---|---|
| `/` | `TodoPage` | 날짜 선택 + 할 일 입력 + 목록 |
| `/todo/:id` | `TodoDetailPage` | 할 일 상세 (세부사항 입력) |
| `/recommend` | `RecommendPage` | 외부 API 추천 할 일 (5주차) |
| `*` | `NotFoundPage` | 없는 주소일 때 안내 |

#### 폴더 / 컴포넌트 구조

```
main.jsx                  ← BrowserRouter로 App 감싸기
App.jsx                   ← 공통 state + Routes/Route로 주소별 페이지 연결
├─ components/Header.jsx  ← 모든 페이지 공통 메뉴 (NavLink)
└─ pages/
   ├─ TodoPage.jsx        ← "/"
   ├─ TodoDetailPage.jsx  ← "/todo/:id"
   ├─ RecommendPage.jsx   ← "/recommend"
   └─ NotFoundPage.jsx    ← "*"
```

#### 1. 설치 & BrowserRouter (`src/main.jsx`)

```bash
npm install react-router-dom
```

라우팅 기능을 쓰려면 앱 전체를 `BrowserRouter`로 감싸야 한다.

```jsx
<BrowserRouter>
  <App />
</BrowserRouter>
```

#### 2. Routes / Route로 페이지 연결 (`src/App.jsx`)

`path`(주소)와 `element`(보여줄 컴포넌트)를 짝지어준다.
`todos`, `date`처럼 **여러 페이지가 같이 쓰는 state는 공통 부모인 App에 두고** props로 내려준다. 그래서 페이지를 이동해도 할 일이 사라지지 않는다.

```jsx
<Header />
<Routes>
  <Route path="/" element={<TodoPage todos={todos} ... />} />
  <Route path="/todo/:id" element={<TodoDetailPage todos={todos} ... />} />
  <Route path="/recommend" element={<RecommendPage date={date} onAdd={addTodo} />} />
  <Route path="*" element={<NotFoundPage />} />
</Routes>
```

- `<Header />`는 `Routes` 밖에 있어서 모든 페이지에 항상 보인다
- `path="*"`는 위에서 걸리지 않은 나머지 모든 주소

#### 3. 페이지 간 이동 방법 3가지

**① NavLink - 상단 메뉴** (`src/components/Header.jsx`)

`Link`와 같지만 현재 주소와 일치하면 `active` 클래스가 자동으로 붙어서 CSS로 "지금 보고 있는 메뉴"를 표시할 수 있다.
`end`를 붙이면 `/`가 `/recommend`에서도 active 되는 걸 막는다.

```jsx
<NavLink to="/" end>내 할 일</NavLink>
<NavLink to="/recommend">추천 할 일</NavLink>
```

```css
.nav a.active { color: #4f7cff; font-weight: bold; }
```

**② Link - 할 일 클릭 → 상세 페이지** (`src/components/TodoItem.jsx`)

`<a href>`를 쓰면 페이지 전체가 새로고침돼서 state가 날아간다. `Link`는 새로고침 없이 주소만 바꿔준다.

```jsx
<Link to={`/todo/${todo.id}`}>{todo.text}</Link>
```

**③ useNavigate - 코드로 이동 (뒤로가기 버튼)** (`src/pages/TodoDetailPage.jsx`)

```jsx
const navigate = useNavigate();
<button onClick={() => navigate(-1)}>← 뒤로</button>  // -1 = 브라우저 뒤로가기
```

#### 4. useParams로 주소 값 꺼내기 (`src/pages/TodoDetailPage.jsx`)

`/todo/:id`의 `:id` 자리에 들어온 값을 꺼내서 해당 할 일을 찾는다.
주소에서 꺼낸 값은 **문자열**이라 `Number()`로 바꿔서 비교해야 한다.

```jsx
const { id } = useParams();            // "/todo/1727..." → id = "1727..."
const todo = todos.find((todo) => todo.id === Number(id));

if (!todo) return <p>할 일을 찾을 수 없어요</p>;  // 없는 id 처리
```

#### 정리

| 개념 | 적용한 곳 |
|---|---|
| 라우터 설정 | `main.jsx`의 `BrowserRouter` |
| 주소별 페이지 연결 | `App.jsx`의 `Routes` / `Route` (4개 페이지) |
| 메뉴 이동 + 현재 메뉴 표시 | `Header.jsx`의 `NavLink` + `.active` |
| 링크 이동 | `TodoItem.jsx`, `RecommendPage.jsx`의 `Link` |
| 코드로 이동 | `TodoDetailPage.jsx`의 `useNavigate` |
| 동적 주소 값 | `/todo/:id` + `useParams` |
| 페이지 간 데이터 공유 | 공통 state를 App에 두고 props로 전달 |

## 5주차 - 외부 API 데이터 출력

> `fetch`로 외부 API를 호출하고, 받아온 데이터를 `useEffect` + `useState`로 화면에 출력

### 구현 내용

**추천 할 일 페이지(`/recommend`)** 를 만들었다. 외부 API에서 할 일 목록을 받아와 보여주고, 마음에 드는 항목은 버튼 한 번으로 내 할 일에 추가할 수 있다.

- 사용한 API: [DummyJSON - Todos](https://dummyjson.com/docs/todos) (`https://dummyjson.com/todos`) - 회원가입/API 키 없이 쓸 수 있는 무료 연습용 API
- 받아오는 데이터 모양:

```json
{
  "todos": [
    { "id": 11, "todo": "Invite some friends over for a game night", "completed": false, "userId": 104 }
  ],
  "total": 254, "skip": 10, "limit": 5
}
```

#### 1. 상태 준비 (`src/pages/RecommendPage.jsx`)

API 호출은 시간이 걸리고 실패할 수도 있어서 **데이터 / 로딩 / 에러** 세 가지 상태를 같이 관리한다.

```jsx
const [items, setItems] = useState([]);       // 받아온 데이터
const [loading, setLoading] = useState(true); // 불러오는 중인지
const [error, setError] = useState(null);     // 에러 메시지
const [skip, setSkip] = useState(0);          // 몇 번째부터 가져올지
```

#### 2. useEffect + fetch로 API 호출

컴포넌트 안에서 바로 `fetch`하면 렌더링될 때마다 계속 호출된다. 그래서 `useEffect`로 감싸고 **의존성 배열 `[skip]`** 을 줘서 처음 화면에 나타날 때와 `skip`이 바뀔 때만 호출되게 했다.

```jsx
useEffect(() => {
  fetch(`${API_URL}?limit=${LIMIT}&skip=${skip}`)
    .then((res) => {
      if (!res.ok) throw new Error(`요청 실패 (${res.status})`); // 404, 500 등
      return res.json();          // 응답(JSON)을 자바스크립트 객체로 변환
    })
    .then((data) => {
      setItems(data.todos);       // 받아온 배열을 state에 저장 → 화면 다시 그림
      setError(null);
    })
    .catch((err) => setError(err.message)) // 네트워크 오류 등
    .finally(() => setLoading(false));     // 성공이든 실패든 로딩 끝
}, [skip]);
```

- `fetch`는 404/500이어도 에러를 던지지 않아서 `res.ok`로 직접 확인해야 한다

#### 3. 상태에 따라 다른 화면 (조건부 렌더링)

```jsx
{loading && <p>불러오는 중...</p>}
{!loading && error && <p className="error">{error}</p>}
{!loading && !error && (
  <ul>
    {items.map((item) => (
      <li key={item.id}>
        {item.todo}
        <button onClick={() => handleAdd(item)}>추가</button>
      </li>
    ))}
  </ul>
)}
```

#### 4. 다른 추천 보기 - state를 바꿔서 다시 호출

버튼을 누르면 `skip`을 랜덤 값으로 바꾼다 → 의존성 배열의 값이 바뀌었으니 `useEffect`가 다시 실행돼서 새 데이터를 받아온다.

```jsx
const handleRefresh = () => {
  setLoading(true);
  setSkip(Math.floor(Math.random() * 250));
};
```

#### 5. API 데이터를 내 할 일에 추가 (4주차 라우팅과 연결)

App에서 내려준 `onAdd`로 현재 선택된 날짜의 할 일에 추가한다. 이미 추가한 항목은 버튼을 "추가됨"으로 바꾸고 비활성화한다.
state가 App에 있어서 `내 할 일` 페이지로 이동하면 추가한 항목이 바로 보인다.

```jsx
const handleAdd = (item) => {
  onAdd(item.todo);
  setAddedIds([...addedIds, item.id]);
};
```

#### 정리

| 개념 | 적용한 곳 |
|---|---|
| 외부 API 호출 | `fetch("https://dummyjson.com/todos?limit=5&skip=...")` |
| JSON 변환 | `res.json()` |
| 호출 시점 제어 | `useEffect(() => { ... }, [skip])` |
| 로딩 / 에러 처리 | `loading`, `error` state + `res.ok` 확인 + `.catch()` |
| 받아온 데이터 출력 | `items.map()`으로 리스트 렌더링 |
| API 데이터 활용 | "추가" 버튼으로 내 할 일에 넣기 |
