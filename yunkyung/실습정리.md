# 리액트 스터디 실습 정리 - 투두리스트

## 2주차 - Rendering / Component 분리

> 배열 데이터를 활용해 리스트 출력, 반복되는 UI를 컴포넌트로 분리, Props를 이용해 데이터 전달

### 구현 내용

투두리스트의 **화면 출력 부분**을 구현했다. 아직 상호작용(추가/삭제 등)은 없고, 미리 정해둔 배열 데이터를 화면에 그리는 것까지가 목표.

#### 컴포넌트 구조

```
App.jsx            ← todos 배열 데이터 정의, TodoList에 props로 전달
└─ TodoList.jsx    ← todos.map()으로 반복 렌더링
   └─ TodoItem.jsx ← todo 하나를 props로 받아 출력
```

#### 1. 배열 데이터 정의 (`src/App.jsx`)

할 일 목록을 객체 배열로 만들고, `TodoList` 컴포넌트에 `todos`라는 이름의 props로 넘겨준다.

```jsx
const todos = [
  { id: 1, text: "리액트 스터디 예습", done: true },
  { id: 2, text: "투두리스트 만들기", done: false },
  { id: 3, text: "과제 제출", done: false },
];

<TodoList todos={todos} />
```

#### 2. 배열을 map()으로 리스트 출력 (`src/components/TodoList.jsx`)

props로 받은 `todos` 배열을 `map()`으로 순회하면서 `TodoItem`을 하나씩 만든다.
리스트를 렌더링할 때는 각 요소에 고유한 `key`를 꼭 지정해야 한다 (React가 어떤 항목이 바뀌었는지 구분하기 위해).

```jsx
function TodoList({ todos }) {
  return (
    <ul className="todo-list">
      {todos.map((todo) => (
        <TodoItem key={todo.id} todo={todo} />
      ))}
    </ul>
  );
}
```

#### 3. 반복되는 UI를 컴포넌트로 분리 (`src/components/TodoItem.jsx`)

`<li>` 한 줄이 계속 반복되므로 `TodoItem` 컴포넌트로 분리했다.
props로 `todo` 객체 하나를 받아서 텍스트와 완료 여부를 표시한다.

```jsx
function TodoItem({ todo }) {
  return (
    <li className="todo-item">
      <span className={todo.done ? "done" : ""}>{todo.text}</span>
      <span className="badge">{todo.done ? "완료" : "진행중"}</span>
    </li>
  );
}
```

#### 정리

| 개념 | 적용한 곳 |
|---|---|
| 배열 데이터 → 리스트 출력 | `TodoList.jsx`에서 `todos.map()` |
| 반복 UI 컴포넌트 분리 | `<li>` → `TodoItem` 컴포넌트 |
| Props로 데이터 전달 | `App → TodoList (todos)`, `TodoList → TodoItem (todo)` |

## 3주차 - State / 이벤트 처리

> `useState`로 상태 관리, 이벤트(onClick / onChange / onSubmit)로 상태 변경, 자식 → 부모로 이벤트 함수 전달

### 구현 내용

2주차에는 미리 정해둔 배열을 화면에 그리기만 했다면, 이번 주에는 **직접 입력하고 바꿀 수 있는 투두리스트**를 만들었다.

- 날짜를 고르고 그 날의 할 일을 **순서대로** 적는다 (1, 2, 3… 번호 표시)
- 체크박스로 완료 표시, 삭제 버튼으로 삭제
- 할 일을 **클릭하면 상세 화면**으로 들어가서 세부사항을 적을 수 있다

#### 컴포넌트 구조

```
App.jsx              ← 상태(date, todos, selectedId)와 상태를 바꾸는 함수들을 가짐
├─ TodoForm.jsx      ← 할 일 입력 폼 (onAdd)
├─ TodoList.jsx      ← 선택한 날짜의 할 일을 map()으로 출력, 순서 번호 전달
│  └─ TodoItem.jsx   ← 번호 / 체크박스 / 제목(클릭) / 삭제
└─ TodoDetail.jsx    ← 클릭한 할 일의 상세 화면 (세부사항 입력)
```

#### 1. useState로 상태 만들기 (`src/App.jsx`)

화면에서 바뀌는 값은 모두 state로 관리한다. 각 할 일에는 어떤 날짜의 것인지 `date`와 세부사항 `detail`을 함께 저장한다.

```jsx
const [date, setDate] = useState(getToday());      // 선택한 날짜
const [todos, setTodos] = useState([]);            // 전체 할 일 목록
const [selectedId, setSelectedId] = useState(null); // 클릭한 할 일 (null이면 목록 화면)
```

#### 2. 날짜 선택 (`src/App.jsx`)

`<input type="date">`의 값을 state와 연결하고, 선택한 날짜의 할 일만 `filter()`로 골라서 보여준다.

```jsx
<input type="date" value={date} onChange={(e) => setDate(e.target.value)} />

const todosOfDate = todos.filter((todo) => todo.date === date);
```

#### 3. 할 일 추가 - 입력한 순서 유지 (`src/components/TodoForm.jsx`)

폼 안에 입력값을 state로 두고, 제출하면 부모(App)가 내려준 `onAdd`를 호출한다.
App에서는 기존 배열 **뒤에** 새 할 일을 붙이기 때문에 입력한 순서가 그대로 유지된다.

```jsx
// TodoForm.jsx
const handleSubmit = (e) => {
  e.preventDefault();              // 새로고침 방지
  if (text.trim() === "") return;  // 빈 칸은 추가하지 않음
  onAdd(text.trim());
  setText("");                     // 입력창 비우기
};

// App.jsx
const addTodo = (text) => {
  const newTodo = { id: Date.now(), date, text, detail: "", done: false };
  setTodos([...todos, newTodo]);   // 원본을 직접 바꾸지 않고 새 배열로 교체
};
```

#### 4. 순서 번호 (`src/components/TodoList.jsx`)

`map()`의 두 번째 인자 `index`를 이용해 `index + 1`을 번호로 넘긴다.

```jsx
{todos.map((todo, index) => (
  <TodoItem key={todo.id} order={index + 1} todo={todo} ... />
))}
```

#### 5. 완료 토글 / 삭제 (`src/App.jsx`)

state는 직접 수정하지 않고 `map()` / `filter()`로 **새 배열**을 만들어 `setTodos`에 넣는다.

```jsx
// 완료 토글: 해당 id만 done을 뒤집은 새 객체로 교체
const toggleTodo = (id) => {
  setTodos(todos.map((todo) =>
    todo.id === id ? { ...todo, done: !todo.done } : todo
  ));
};

// 삭제: 해당 id만 빼고 새 배열 만들기
const deleteTodo = (id) => {
  setTodos(todos.filter((todo) => todo.id !== id));
};
```

#### 6. 클릭해서 상세 화면 들어가기 (`src/components/TodoDetail.jsx`)

할 일 제목을 클릭하면 `selectedId`에 그 id를 저장하고, App은 `selectedId`가 있으면 목록 대신 상세 화면을 보여준다 (조건부 렌더링).
상세 화면의 `<textarea>`에 입력하면 바로 해당 할 일의 `detail`이 바뀐다.

```jsx
// TodoItem.jsx - 제목 클릭
<button className="text-button" onClick={() => onSelect(todo.id)}>
  {todo.text}
</button>

// App.jsx - 선택한 할 일이 있으면 상세 화면
const selectedTodo = todos.find((todo) => todo.id === selectedId);
if (selectedTodo) {
  return <TodoDetail todo={selectedTodo} onChangeDetail={updateDetail}
                     onBack={() => setSelectedId(null)} />;
}

// TodoDetail.jsx - 세부사항 입력
<textarea
  value={todo.detail}
  onChange={(e) => onChangeDetail(todo.id, e.target.value)}
/>
```

세부사항이 적혀 있는 할 일은 목록에서 📝 아이콘으로 표시된다.

#### 정리

| 개념 | 적용한 곳 |
|---|---|
| `useState`로 상태 관리 | `date`, `todos`, `selectedId`, 입력창 `text` |
| 이벤트 처리 | `onChange`(날짜·입력·체크박스·세부사항), `onSubmit`(추가), `onClick`(삭제·상세 이동·뒤로가기) |
| 불변성 유지 | `[...todos, newTodo]`, `map()`으로 수정, `filter()`로 삭제 |
| 자식 → 부모로 이벤트 전달 | `onAdd`, `onToggle`, `onDelete`, `onSelect`, `onChangeDetail` props |
| 조건부 렌더링 | 할 일이 없을 때 안내 문구, `selectedId`가 있으면 상세 화면 |
